# Метрики приложения: что измеряется и как смотреть

Проект автоматически собирает метрики в **CSV-файлы** (никакого SQL не нужно —
открываете в Excel или одной командой Python). Все метрики разделены на
**технические** (надёжность системы) и **бизнесовые** (эффективность алгоритма).

---

## 0. Сводная таблица метрик проекта (по типу гипотезы)

| Тип гипотезы | Имя | Формула | Где считается | Статус |
|---|---|---|---|---|
| Бизнес | **CTR превью** | `клики_[Смотреть видео] ÷ сессии` | фронт `business_summary().ctr_preview_pct` | 🟢 авт |
| Бизнес | **CR (конверсия в заявку)** | `заявки ÷ сессии` | фронт `business_summary().conversion_rate_cr_pct` | 🟢 авт |
| Бизнес | **VCR (досмотры)** | `video_completed ÷ video_play` | фронт `business_summary().video_completion_rate_vcr_pct` | 🟢 авт (кастомный HTML5-плеер) |
| Бизнес | **TTL (время до лида)** | `ts[лид] − ts[первый заход]` (по Client ID) | фронт `ttl_seconds_for()` / `business_summary()` | 🟢 авт |
| ML | **Hit Ratio Top-3** | `совпадения выбранного_признака == макс_SHAP_в_группе ÷ всего_групп` | бэк `summary.hit_ratio_top3_factors` | 🟢 авт |
| ML | **DFP (доминирование фактора)** | `1 − (инференсов с mismatch ÷ успешных)` | бэк `summary.dominant_feature_precision_dfp` | 🟢 авт |
| ML | **Share High-Confidence** | `успешных без mismatch ÷ успешных` | бэк `summary.share_high_confidence_predictions` | 🟢 авт |
| ML | **Accuracy классификатора** | `верно предсказанных класса ÷ всего` | на размеченном тест-сете | 🔴 ручной |
| ML | **Spearman ρ (SHAP↔просмотр)** | корреляция рангов SHAP и времени просмотра фрагментов | плеер пишет `video_segment_watch`; ρ считает `tools/view_metrics.py` по стандартным длительностям сегментов | 🟢 авт |
| ML | **QAR / FID (качество ролика)** | `валидных_роликов ÷ всего_попыток` + FID для реалистичности | ручная / MTurk-проверка | 🔴 ручной |
| Инж | **Render Latency** | `total_ms` / `render_ms` | бэк `metrics.csv` | 🟢 авт |
| Инж | **Error Rate** | `успешных=0 ÷ всех` | бэк `summary.error_rate_pct_rounded_2` | 🟢 авт |
| Инж | **Cost per Inference** | `Σ render_ms×тариф ÷ инференсов` | бэк `summary.est_cost_per_inference_usd` | 🟢 авт |

> 🟢 = собирается автоматически · 🟡 = нужна доработка сбора · 🔴 = нужен внешний источник данных / ручная проверка.

### Где смотреть метрики, которые НЕ собираются автоматически
- **Hit Ratio Top-3** — после сделки сопоставить `top_factors` (в `metrics.csv`
  бэкенда) с тем, что реально назвал покупатель при обзвоне; формула — доля
  совпадений топ-3. Источник: CSV-логи бэкенда + CRM/обзвон.
- **Accuracy** — возьмите размеченный набор «вектор признаков → реальный класс
  посёлка», прогоните `GET /predict` и сравните; формула — доля верных.
- **Spearman ρ** — нужен плеер, отдающий время просмотра на фрагмент
  (см. «VCR»): сопоставьте ранги `ranked_factors` и времени просмотра.
- **QAR / артефакты ролика** — ручная/MTurk-проверка N роликов: доля без
  артефактов и рассинхрона.
- **Cost per Inference** — точные цифры в **Yandex Cloud → контейнер**
  (Serverless Containers, метрики инвоков/CPU-времени) или в **смете по
  Object Storage** (за S3-трафик). Текущая оценка использует
  `CPU_SECOND_PRICE_USD` (по умолчанию ~0.000005 $/CPU-сек).

## 1. Какие метрики реально замеряются кодом

### Бизнес-метрики (frontend, файл `frontend/analytics_output/`)
| Метрика | Что считается | Откуда данные |
|---------|---------------|---------------|
| **CTR превью** | клики «Смотреть видео» / число сессий | `events.csv` (`preview_click`) ÷ `sessions.csv` |
| **Конверсия в лид (CR)** | лиды «Заказать звонок» / число сессий | `events.csv` (`lead_submit`) ÷ `sessions.csv` |
| **Time-to-Lead (TTL)** | время от первого захода до лида (по одному Client ID) | разница `sessions.ts_iso` и `events.ts_iso` |
| **Latency (клиент→сервер)** | время запроса `/generate/` | `events.csv` (`latency_record`) |

### Технические метрики (backend, файл `backend/data_metrics/`)
| Метрика | Что считается | Откуда данные |
|---------|---------------|---------------|
| **Latency генерации** | общее время `/generate/` | `metrics.csv` (`total_ms`) |
| **Render Time** | время склейки видео | `metrics.csv` (`render_ms`) |
| **Download time** | время скачивания фрагментов из S3 | `metrics.csv` (`download_ms`) |
| **Error Rate** | доля неуспешных запросов | `metrics.csv` (`success=0`) |
| **Cost per Inference** | CPU-секунды рендера × тариф | `summary.csv` |

### Данные для DS-метрик (backend, `metrics.csv`)
На каждый инференс пишутся: предсказанный класс, посёлок, топ-SHAP-факторы,
число скачанных фрагментов. Это основа для:
- **Accuracy/Precision классификатора** — сравните предсказанный класс с тем,
  куда реально обратился покупатель (по лидам).
- **Корреляции SHAP и просмотра фрагмента** — в `ranked_factors` зафиксирован
  порядок важности; время просмотра каждой части (при добавлении плеера с
  событиями) можно сопоставить с этим порядком.

> **Честное ограничение.** Глубина просмотра (VCR), корреляция просмотра
> отдельных фрагментов и A/B-тест требуют плеера с событиями (например,
> HTML5 `<video>` API) и разделения трафика по группам. В чистом
> Streamlit `st.video` таких событий нет. Эти метрики вписаны как **подготовка
> данных** (`ranked_factors` уже сохраняется), а сам факт просмотра ролика
> помечается кнопкой «Смотреть видео».

> **⚠️ Файловая система Serverless Container эфемерна** — после перезапуска/
> revision-деплоя содержимое `data_metrics/` исчезает. **Решение встроено**:
> если заданы S3-переменные (те же, что и для видео), backend **автоматически**:
> - при старте **скачивает** накопленный `metrics.csv` из S3 (метрики продолжают
>   копиться, не обнуляются);
> - после **каждого** инференса **загружает** `metrics.csv` и `summary.csv` обратно
>   в бакет, в папку `metrics/` (префикс настраивается через `METRICS_S3_PREFIX`).
>
> Это значит: метрики backend теперь переживают рестарты. Скачивать их оттуда
> можно вручную (строка ниже) или просто смотреть локальные CSV, пока контейнер
> работает. Метрики **frontend** (Streamlit на постоянной VM/Cloud) хранятся
> стабильно и без S3.
>
> Скачать накопленные метрики из S3 вручную (пример для YC-инструментария):
> ```
> # через консоль Yandex Cloud или S3-клиент (s3cmd, aws cli, Cyberduck):
> # 1) скачать:  s3://<bucket>/metrics/metrics.csv
> # 2) или запросить у бэкенда:  GET {BACKEND_URL}/metrics  ->  s3_backup.remote_csv
> ```

## 3. Как посмотреть метрики

### Способ А. Отчёт одной командой (рекомендую)
```bash
python tools/view_metrics.py
```
Выведет удобную сводку: Error Rate, Latency avg/p50/p95, Render, CTR, CR, TTL.

Отчёт можно запустить и для другой папки проекта:
```bash
python tools/view_metrics.py C:\путь\к\папке
```

### Способ Б. Открыть CSV в Excel
1. Откройте Excel.
2. **Файл → Открыть** → в поле типа файлов выберите **«Все файлы (*.*)»**.
3. Выберите `backend/data_metrics/metrics.csv` (или любой другой).
4. Мастер импорта: укажите разделитель **запятая**, кодировку **UTF-8**.
   > Файлы сохранены с BOM (`utf-8-sig`), поэтому русские буквы отобразятся
   > правильно.
5. Готово — дальше можно строить сводные таблицы/графики.

Если файл открывается «криво» (всё в одной ячейке) — значит Excel не узнал
разделитель: продублируйте импорт вручную через меню (шаг 3–4).

### Способ В. Через Python/Pandas
```bash
python -c "import pandas as pd; print(pd.read_csv('backend/data_metrics/metrics.csv'))"
python -c "import pandas as pd; print(pd.read_csv('backend/data_metrics/summary.csv'))"
```

### Способ Г. Через эндпоинт бэкенда
Пока backend запущен, сводку можно получить по адресу:
```
http://<BACKEND_URL>/metrics      (вернёт JSON)
```

## 4. Как открыть консоль разработчика (DevTools) — для ручной проверки

Если хотите вручную посмотреть, что происходит в браузере (события, сетевые
запросы, консоль), откройте **Инструменты разработчика (DevTools)**:

1. Откройте приложение в браузере (Chrome/Edge/Firefox).
2. **Клик правой кнопкой мыши** в любом месте страницы → **«Просмотреть код» /
   «Исследовать»** (Inspect).
   Либо нажмите клавиши **F12** (или **Ctrl+Shift+I** в Chrome/Edge).
3. В открывшейся панели выберите вкладки:
   - **Network (Сеть)** — показывает все HTTP-запросы. Нажмите «Сформировать
     ролик» и найдите запрос на `BACKEND_URL/generate/` → вкладка **Response**
     покажет JSON с ссылкой на видео, вкладка **Timing** — задержки.
   - **Console (Консоль)** — сообщения/ошибки JavaScript (здесь будут
     сообщения от счётчика Client ID).
   - **Application (Приложение) → Cookies** — увидите cookie `tlx_client_id`
     и `tlx_session_ts`, по которым считается TTL.

> Для проверки сетевых запросов к бэкенду удобнее всего вкладка **Network**:
> ставьте метку времени столбца *Time*, фильтруйте по `generate`, и вы увидите
> точное время ответа.

## 5. Что автоматически попало в код

**Backend** (`backend/main.py`, `backend/metrics.py`):
- `metrics.py` — запись каждого инференса в CSV и сводку, а также **S3-sync**:
  восстановление накопленных метрик при старте и загрузка после каждого
  инференса в папку `{METRICS_S3_PREFIX}metrics.csv`.
- `/generate/` — теперь замеряет `download_ms`, `render_ms`, `total_ms`,
  количество фрагментов, класс, топ-SHAP-факторы, результат.
- `/predict` — тоже логируется.
- `GET /metrics` — отдаёт сводку JSON (включая параметры S3-бэкапа).

**Frontend** (`frontend/app.py`, `frontend/analytics.py`):
- Логирование каждой сессии (`sessions.csv`) с Client ID (cookie).
- Кнопка **«Смотреть видео»** → событие `preview_click`.
- Форма **«Заказать звонок»** → событие `lead_submit` (лид).
- Замер `latency_ms` на каждый запрос генерации → `latency_record`.
- Показ топ-SHAP-факторов (подготовка данных для корреляции).
- `analytics.py` — модуль CSV-записи событий.

**Отчёт** (`tools/view_metrics.py`) — читает все CSV и печатает сводку.
