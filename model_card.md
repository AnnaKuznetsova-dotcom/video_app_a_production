# Model Card: Классификатор посёлка для каталога видеобъектов (вариант A)

## 1. Общие сведения о модели (Model details)

| Параметр | Описание |
|---|---|
| **Название модели** | `global_best_model.joblib` |
| **Версия сервиса** | 2.1.0 (production-standards, pipeline-структура) |
| **Тип задачи** | Многоклассовая классификация |
| **Алгоритм** | XGBoost (градиентный бустинг деревьев) |
| **Домен** | Табличные данные анкеты покупателя элитной недвижимости |
| **Автор** | AnnaKuznetsova-dotcom |
| **Лицензия** | Внутреннее использование проекта `video_app_a_production` |
| **Формат сериализации** | `joblib` (scikit-learn / xgboost) |
| **Инфраструктура инференса** | Yandex Serverless Container (FastAPI) |
| **Источник расчёта** | Ноутбук с расчётом модели (Colab): <https://colab.research.google.com/drive/11DuvWTXvnml5HbQoV3ubGGYTxtuUFP8a?usp=sharing> |

Модель предсказывает, какой из посёлков элитных таунхаусов в Подмосковье
наиболее подходит покупателю по анкетным данным. **Ролик фиксированный по
посёлку (вариант A): он одинаковый для всех пользователей с одинаковым
классом, видео не персонализируется.**

## 2. Назначение и бизнес-задача (Intended use)

### 2.1. Бизнес-задача
Быстрое релевантное предложение вместо общего каталога: по анкете покупателя
сервис сразу показывает готовый видеоролик подходящего посёлка.

### 2.2. Что решает модель
- Определяет **наиболее релевантный посёлок** по ответам анкеты.
- Сервис отдаёт готовый видеоролик этого посёлка (видео собрано заранее и
  лежит в бакете `video/Kaskad_Video/`).

### 2.3. Где встроена модель (диаграмма эксплуатации)
```
Анкета на сайте (Streamlit)
        ↓
Вектор признаков (42 фичи)
        ↓
[global_best_model] → класс посёлка
        ↓
Фиксированный ролик посёлка (S3: video/Kaskad_Video/<посёлок>.mp4)
        ↓
Публичная ссылка → покупатель → лид-форма
```

### 2.4. За счёт чего модель приносит эффект
- **Скорость**: запрос → ролик за секунды, без участия менеджера.
- **Релевантность**: вместо каталога — посёлок под ответы анкеты.
- **Масштабируемость**: одинаковое качество ответа при любом трафике
  (serverless, холодный старт ≈ 0.1–14 с, дальше инференс < 1 с).
- **Контроль качества (вариант A)**: видео фиксированное, качество reassuring
  и измеримое (QAR-проверка роликов).

## 3. Входные и выходные данные (Inputs / Outputs)

### 3.1. Входные данные
JSON-объект `features` — полный вектор из **42 признаков** анкеты
(в исходных данных было **83 признака**, после отбора — 42):

| Группа | Примеры колонок |
|---|---|
| Планировка квартиры | `bin_num__квартира_планировка_1_комн` … `_студия`, `_missing` |
| Приоритеты | `безопасность`, `инфраструктура`, `контингент`, `природа_экология`, `транспортная_доступность`, `missing` |
| Отделка | `white_box`, `под_ключ`, `под_отделку`, `missing` |
| Цель приобретения | `для_сдачи_в_аренду`, `дополнительное_жилье`, `инвестирование`, `missing` |
| Способ покупки | `ипотека`, `материнский_капитал`, `полная_оплата`, `продажа имеющегося жилья`, `рассрочка`, `missing` |
| Схема оплаты | `ипотека`, `рассрочка`, `100процент_оплата`, `стандартная_схема` |
| Площадь | `ord__ранг_площади` (порядковый ранг 0…7) |
| Количество комнат | `few_cat__количество_комнат_1.0` … `4.0` |
| Семья / дети / авто | `семейное_положение_*`, `есть_ли_дети_*`, `наличие_автомобиля_*` |

Пропуски анкеты размечены категорией `missing`; область видимости — полный
вектор по списку `backend/data/feature_names.txt` (контракт —
`backend/pipeline/feature_generation.py`).

### 3.2. Выходные данные
| Поле | Тип | Описание |
|---|---|---|
| `klass` | int | Числовой класс |
| `settlement` | string | Название предсказанного посёлка |
| `variant` | string | `${klass}_базовый_${settlement}` |
| `video_url` | string | Публичная ссылка на фиксированный ролик |

## 5. Данные для обучения и оценки (Data)

### 5.1. Датасет и версия данных
| Параметр | Значение |
|---|---|
| **Строк (размер датасета)** | **3233** |
| **Признаков в исходных данных** | **83** |
| **Признаков после отбора (в модели)** | **42** (отбор: удаление редких/нулевых одно-hot колонок из 83) |
| **Сплит** | train 70% (≈2263) / val 15% (≈485) / test 15% (≈485), стратифицированно, `random_state=42` |
| **Целевая переменная** | класс посёлка (4 класса: Kaskad_Park, Akademia_Park, Fedoskino_Park, Park_Aprel) |

Датасет — версия `dataset_v<дата заморозки>.csv`; при переобучении датасет
версионируется заново (см. `Model_retrain_BPMN.md`, этап 3).

Далее — источники и правила предобработки:

### 5.2. Предобработка
- Пропуски → категория `missing` внутри группы.
- Площадь: 20–30 → 1; 30–40 → 2; 40–50 → 3; 50–60 → 4; 60–70 → 5; 70–80 → 6;
  ≥ 80 → 7; вне диапазона → `ord__ранг_площади = 0`.
- One-hot внутри групп (`bin_num__*`, `few_cat__*`).
- Целевая переменная — класс посёлка (`CLASS_MAP`: Kaskad_Park, Akademia_Park,
  Fedoskino_Park, Park_Aprel).

### 5.3. Ограничения по данным
- Датасет собран из аудитории элитных таунхаусов Подмосковья; перенос на
  другие сегменты недвижимости не рекомендуется.
- Переобучение требуется при появлении нового класса (нового посёлка).

## 6. Ограничения и границы применимости (Caveats and recommendations)

### 6.1. Когда модель работает хорошо
- Вектор признаков полностью заполнен корректно (или явно `missing`).
- Покупатель относится к целевому сегменту (элитные таунхаусы Подмосковья).
- Для предсказанного посёлка загружен фиксированный ролик в S3.

### 6.2. Когда модель может ошибаться
- Аномальные комбинации ответов, не встречавшихся в обучении.
- Новый посёлок (новый класс) отсутствует в обучении — **модель не может
  его предсказать**; требуется переобучение (см. Model_retrain_BPMN.md).
- Дрейф распределения предсказаний при любых отказах более чем на 20%.
- Сбои в S3/отсутствие ролика → `/health = degraded`, ошибки генерации.

### 6.3. Рекомендации по использованию
- Перед вводом модель проходит карантин 7 дней (канареечный деплой).
- Переобучение — при дрейфе, накоплении данных и **при вводе нового посёлка**.
- Финальную замену модели одобряет владелец бизнеса (human-in-the-loop).

## 7. Bias / Fairness анализ

### 7.1. Известные смещения
- **Географическое смещение**: данные — из лидов KASKAD; пользователи из
  других сегментов могут иметь иную специфику.
- **Социально-экономическое смещение**: анкета ориентирована на сегмент
  элитного жилья; для массового жилья модель неприменима.
- **Небаланс классов**: если посёлок встречается чаще, вероятность может
  быть завышена — лимит в валидации данных: один класс ≤ **80%** выборки.

### 7.2. Снижение рисков
- Стратифицированное разбиение и нормализация классов при обучении.
- Мониторинг распределения предсказанных классов в production
  (± 10% от baseline в течение карантина).
- При добавлении нового класса — обязательная проверка точности этого класса
  и отсутствие конфликтов со старыми классами.

## 8. Этические соображения и соответствие

- Модель **не использует** персональные данные (ФИО, телефон) — только
  анкетные предпочтения; телефон собирается отдельно лид-формой.
- Все версии модели и датасетов версионируются, решение о замене модели —
  под подписью владельца бизнеса.
